# UI fix pass: target 10/10 in every area, both themes, every width

Each item states the acceptance test QA will apply.

## 1. "How the test works" strip (top of Overview, above the hero)
Four steps in a row (a 2x2 grid below 900 px, one column below 560 px), each an image with a one-line caption:
1. **The kit**: the loose parts exactly as the model receives them (`tasks/<kit>/build/kit_marked.png` without the red dots; add a `kit_sheet.png` build output if needed via a new server-side render of the kit layout, never showing attach points).
2. **The instruction**: a short quote card: "Assemble a working excavator." plus "No coordinates, no list of which hole goes where."
3. **The model's answer**: one model assembly of the same kit.
4. **The verdict**: the same assembly with failed joints circled red and correct positions green, and "2 of 17 connections wrong → fail".
Use one kit where a frontier model fails on a clearly visible mistake. Acceptance: a reader who knows nothing can say what the model is asked to do and how it is graded after looking only at this strip.

## 2. Plain-language hero
- One sentence, under 25 words, no condition letters, written so it stays true for any data: e.g. "Told exactly how to fit the parts, the best model gets {C}% right. Asked to work it out, {A}%. With unlabelled parts, {B}%." Numbers from the API.
- One comparison, not four images: the most striking failure as a single before/after slider with the error ring and label, plus "Open this trial".
- Acceptance: no jargon above the fold; numbers match `/api/overview`.

## 3. Correct-assembly alignment (trial view slider, replay ghosts, hero)
The correct assembly is shown aligned to where the model placed its base part: reference matrices are pre-multiplied by `model_base @ inv(ref_base)` (rotation and translation of the base part only). Applies to the slider's "Correct" side, replay green ghosts and any side-by-side. Acceptance: for a trial whose only fault is one part, every other part of the ghost overlays the model's part exactly.

## 4. Responsive
- Nav: at < 900 px a horizontally scrollable tab bar with fade edges and the theme toggle as an icon button that never overlaps the tabs.
- No horizontal page overflow on any route at 390 px (Run live included).
- Charts: at 390 px labels never overlap; ladder value labels move inside or wrap; legends wrap.
- Acceptance: `scrollWidth <= clientWidth` on every route at 390/1024/1440; no clipped text in screenshots.

## 5. Tighter Overview
Order: How the test works → hero → stat tiles → difficulty ladder → what goes wrong → per-kit heatmap → top 6 mistakes with "See all mistakes" (opens Failures) → how it is graded.
Glossary tooltips (an info icon with a popover, keyboard reachable) on: B / A / C, full pass, score, tolerance, pass^k.
Acceptance: Overview under about 3,800 px at 1440 px wide.

## 6. Visual identity and polish
- Type scale: page title 40/48, section title 22/28, body 15/24, small 13/20; consistent across pages.
- One accent (`--accent`) used for primary actions and active nav only.
- Each section gets a one-line intro under its title.
- Dark mode: drawings sit on a dark paper tone (`#2a2925` card with the drawing's own cream canvas inset with a 1px border) so there is no glaring white block; images keep their colours.
- Cards: consistent radius 12 px, padding 24 px, shadow tokens, no double borders.
- Buttons: one primary style, one secondary style, same height everywhere.
- Acceptance: QA rates look and feel 10/10 in both themes.
