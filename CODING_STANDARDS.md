# Coding standards

Applies to every file in the package. Each standard is checked in the final review (RULES.md R29).

## 1. Structure
```
kit-assembly-eval/
├── README.md               judges read this first
├── STORY.md  RULES.md  CODING_STANDARDS.md  CHECK_REPORT.md
├── requirements.txt        pinned versions
├── .env.example            key names only
├── run_eval.py             CLI: run models, save results
├── kitbench/               library (no CLI code, no prints)
│   ├── __init__.py         version string only
│   ├── templates.py        prompt templates (string constants) + fill()
│   ├── draw.py             drawing helpers used by task files
│   ├── geometry.py         transform parsing, matrix helpers
│   ├── kit.py              load task, bake parts, reference solution, anonymous ids
│   ├── grader.py           placements + checks -> grade dict
│   ├── models.py           provider calls, retries, usage
│   └── render.py           SVG -> PNG
├── tasks/<kit>/
│   ├── task.py             parts, features, connections, tolerances; may contain drawing code for its own parts
│   ├── art/                source artwork copied into the project (bike, pulley)
│   └── build/              generated: kit.svg, reference_solution.svg, reference.png, kit_marked.png
├── scripts/                build_all.py, regrade.py, summarize.py, render_failures.py, check_package.py
├── tests/                  pytest: grader, templates, determinism
├── results/<condition>/<kit>/<model>__t<k>.json
├── transcripts/            selected results, copied verbatim
└── figures/                images used in README and video
```
One job per module. Library code never reads environment variables except models.py, and never prints.

## 2. Python
- Python 3.11+. Standard library first; third-party only: numpy, svgelements, pytest, anthropic, google-genai.
- Type hints on every public function. One-line docstring on every public function.
- Names: snake_case functions and variables, UPPER_CASE constants, no abbreviations beyond common ones (svg, px, deg).
- Functions short and single-purpose; no function over about 40 lines without a reason.
- No global mutable state. No randomness at run time; anything seeded is seeded from the kit name.
- Pure functions in geometry.py and grader.py: same input, same output, no I/O.
- Paths built with pathlib relative to the package root; never absolute.

## 3. Comments
- At most 2 lines per comment, and only to explain why. Never narrate what the code does.
- No TODOs, no commented-out code, no tool or assistant names, no "generated by" lines.

## 4. Errors and edge cases
- Model output is untrusted input. The grader must never crash on it: no SVG, broken XML, unknown ids,
  duplicate parts, mirrored or scaled parts, NaN or huge numbers all produce a clean failing grade with a reason.
- API failures (timeouts, 429, 5xx) are retried with backoff; after the last retry the trial is marked
  "api_error" and excluded from scores, never counted as a model failure.
- Fail loudly on our own mistakes: a broken task file or a reference that fails its own checks stops the build.

## 5. Security and privacy
- Keys only from environment variables (loaded from .env when present). Never logged, never written to results.
- .env is git-ignored and excluded from the ZIP; scripts/check_package.py greps for key patterns.
- Model output is parsed with xml.etree only; it is never executed, never fetched, never rendered with
  external resources enabled.
- No home-directory paths, user names, cloud project ids or employer names anywhere.

## 6. Reproducibility
- Exact model ids and settings live in one place (models.py) and are copied into every result file.
- Each result stores the prompt SHA-256, date, settings, tokens, seconds, full output and grade.
- Re-grading saved outputs needs no keys; summarize.py rebuilds every table from results/.
- Kit build is deterministic; tests compare file hashes across two builds.
- requirements.txt pins exact versions from the environment the results were produced in.

## 7. Testing
- pytest, no network. Covers: every reference passes; each part shifted / rotated / reversed / mirrored /
  scaled / missing / duplicated / swapped fails; valid alternatives pass; malformed model output fails cleanly;
  templates fill identically across kits except for slots; anonymous id mapping round-trips.
- The full suite runs in under a minute.

## 8. CLI and logging
- argparse with --help text on every option. Sensible defaults; --dry-run prints the plan and cost estimate.
- Progress lines to stdout: kit, model, trial, PASS/FAIL, score, seconds. No colour codes, no emoji.
- Re-running skips completed trials, so a crash never loses work.

## 9. Performance and cost
- Concurrency capped (default 6 parallel calls) to respect rate limits.
- Output tokens capped per call; the cap and the measured cost per run are reported in the README.

## 10. Data and licensing
- All artwork is the author's own or drawn for this eval. No third-party images.
- Each task.py states the artwork's origin in a one-line comment.

## 11. Documentation
- README sections follow the guide's list (RULES.md R26). Every number comes from summarize.py output.
- Each kit has a short card in the README: parts, what makes it hard, reference image.
